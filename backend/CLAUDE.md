# Backend — Rust + Axum

You own `backend/`, except its Dockerfile, which is ops'. You do not edit
`frontend/`. If the UI has to change, name the change and stop — that is a
frontend session. To learn what consumes a field, ask `frontend-consultant`.

## Non-negotiable

**You own the wire format, and nothing checks it for you.** `models.rs` is the
contract the frontend reads. `frontend/src/lib/types.ts` is hand-mirrored from it
and is regenerated by nobody. Renaming or removing a serialized field compiles
clean on both sides and breaks the browser at runtime. Ask `frontend-consultant`
before you touch one, every time.

**Know what serde actually puts on the wire.** `#[serde(default)]` governs
*de*serialization. A field is only omitted from a response when it carries
`skip_serializing_if`. This is exactly where the mirror has already drifted:
`types.ts` marks `active_seed_count`, `depth_score`, `cross_validated` and
`taste_alignment` optional, but all four are always emitted. Harmless direction,
but do not add to it — when you add a field, say explicitly whether it is always
present.

**Never block the runtime.** On 2026-07-05 the entire tokio runtime starved and
the service wedged silently for three days. In-runtime timeouts cannot catch
this: the timeout task needs the same starved scheduler. That is why the liveness
watchdog in `main.rs` is an **OS thread** with socket-level read and write
timeouts, not a tokio task.

Any new synchronous file IO, blocking logging, or non-trivial CPU work goes
behind `spawn_blocking`. Every outbound call gets an explicit timeout — Redis
operations are capped at 5s for this reason, and there is a coarse outer
`TimeoutLayer` on the router. Non-blocking logging is the known outstanding
follow-up from that incident.

**Every external API is hostile.** Last.fm serves an application error code
*under* an HTTP 404 body, so a retry layer that reads only the status eats the
real reason — that cost a live bug on 2026-07-04. Spotify answers a burst with a
429 and a multi-hour penalty, so calls are capped and a 429 starts a cooldown.
Read the body, not just the status.

**Optional components stay optional.** No `DATABASE_URL` means persistence off
and `persistence: false` on the response; no `REDIS_URL` means the in-memory
store. `cargo build` and `cargo test` must stay green with neither set. Never
make one of them required.

## The error envelope, and its known gap

Errors go out as `{ "error": "<prose>", "code": <u16> }` from the `envelope`
helper in `api.rs`.

**`code` is currently the HTTP status, which tells a client nothing it can act
on.** A caller cannot distinguish "last.fm auth not configured" from "persistence
not configured" — both are 503 — without string-matching English prose, which is
not something a client should ever do. When you touch an error path, give it a
real symbolic code and keep the message as prose for humans. Branch on the code,
never the sentence.

## Migrations

`backend/migrations/`, plain SQL, applied automatically on startup.

**Additive only, and never edit one that has been applied.** A new column gets a
default or allows null. A removal or rename ships only after you have *verified*
nothing reads it — ask `frontend-consultant` rather than assuming.

## Testing

96 tests across ten modules, run by `cargo test`. Router-level `oneshot` tests
cover the no-DB paths: 400s, 429s, anonymous access, `/api/status`.

**The canary suite is the no-DB router set plus the liveness and timeout
behaviour.** Those are what stand between a config change and another silent
three-day outage, and they are the ones that must never be weakened. A test that
requires a database or a live API key to pass is a test that will be skipped
under pressure.

Test the behaviour that would break discovery, not the framework.

## Rust

Edition 2021, stable toolchain pinned in `rust-toolchain.toml`.

There is **no `clippy.toml` and no clippy step in CI.** Nothing currently refuses
a dated or sloppy construct mechanically, so it falls to review, which is the
wrong place for it. Adding `cargo clippy -- -D warnings` is a cheap, real
improvement; until then, do not restate style in review either.

## Commands

PowerShell-safe.

| Task | Command |
|---|---|
| Build | `cd backend; cargo build --release` |
| Run | `cd backend; cargo run --release` |
| Tests | `cd backend; cargo test` |
| One test | `cd backend; cargo test <name>` |
| Lint (once configured) | `cd backend; cargo clippy -- -D warnings` |
| Format | `cd backend; cargo fmt` |
| Postgres for DB-backed work | `docker compose up -d postgres` |

Name which of these you ran and which you only reasoned about.
